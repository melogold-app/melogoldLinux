# Пульт: часы не показывать среди устройств, на которые можно включить музыку

Статус: открыто

Те же задания: `melogoldAndroid/tasks/0023-hide-watch-remote-target.md`, `melogoldWindows/tasks/0025-hide-watch-remote-target.md`; Apple сделано в ветке `apple/ui-fixes` (`RemoteControl.canPlay`).

Пользователь (2026-10-01): «часы считаются как то, на чём можно играть музыку… бред включать музыку на часах удалённо, да и
приложение нужно ручками открыть, что теряет любой смысл». На скриншоте листа «Устройство» среди «Других устройств»
стояли «Apple Watch · Не в сети».

## Как должно быть

- В списке «Другие устройства» пульта нет устройств с платформой `watchos` (`GET /playback/devices` отдаёт их, как все
  устройства аккаунта). Фильтр — в одном месте, где список приходит от сервера.
- Контракт плеера — `docs/DESIGN-DOCTRINE.md` §4.8, последний пункт.

## Проверка

- Тест: список из Mac и Apple Watch → в пульте только Mac.
- Вручную: аккаунт с часами — в листе «Устройство» часов нет.

## Опыт Windows (сделано там в 0.1.14)

`melogoldWindows`, коммит 8a63b0e: список устройств пульта отдаёт только те, что могут играть
(`RemoteController.CanPlay` — платформа не `watchos`, без учёта регистра); тест «Mac и Apple Watch → только Mac».
Здесь `watchos` уже распознаётся как `DeviceKind::Watch` (`crates/melogold-core/src/devices.rs`) — отфильтровать
по нему список целей пульта (фильтр истории по устройствам часы показывать по-прежнему).
