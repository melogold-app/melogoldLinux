# Поиск: лучший результат первым, крупной карточкой

Статус: сделано — правило `melogold_core::search_top` (карточка YouTube Music, иначе исполнитель с именем запроса), тесты на ответах Windows `tests/fixtures/search/`, карточка `pages/search.rs::top_result_card`. Живые «Кино», «Michael Jackson» в окне не сняты — YouTube с этой машины не открывался; вид — шаг съёмки `07g-top-result-sample`

Те же задания: `melogoldiOSmacOS/tasks/0023-search-top-result.md`, `melogoldAndroid/tasks/0021-search-top-result.md`, `melogoldWindows/tasks/0023-search-top-result.md`.

Пользователь (2026-10-01): «нравится, когда пишешь в поиск автора, а не песню, — он там сразу сам подсвечивается, не нужно
лишний клик делать; нужно добавить во все клиенты» (как в Apple Music).

## Как должно быть

- В выдаче «Всё» первым идёт **лучший результат** — крупная карточка:
  - исполнитель — фото, имя, «Исполнитель», кнопки «Слушать» (радио или популярные треки исполнителя) и открыть страницу;
  - альбом — обложка, название, исполнитель, «Слушать»;
  - трек — обложка, название, исполнитель; нажатие играет.
- Откуда брать: у YouTube Music в выдаче «Всё» первая полка — карточка лучшего результата (`musicCardShelfRenderer`).
  Если её нет, а имя исполнителя из выдачи совпадает с запросом (без учёта регистра, ё/е и знаков), исполнитель
  поднимается первым.
- Остальная выдача — как сейчас, без повтора лучшего результата строкой ниже.
- Контракт поиска — `docs/DESIGN-DOCTRINE.md` §4.6.

## Проверка

- «Кино», «Michael Jackson», «Tkay Maidza» — первым идёт карточка исполнителя, одно нажатие открывает страницу, «Слушать» играет.
- Название известного трека — первым трек; название альбома — альбом.
- Тест разбора выдачи с карточкой лучшего результата и без неё (сохранённые ответы).

## Опыт Windows (сделано там в 0.1.14)

`melogoldWindows`, коммит 7200c8c: разбор `YouTubeMusic.ParseSearchSummary`, правило `Core/Music/SearchTopResult.cs`,
карточка `Controls/TopResultCard.cs`, тесты `SearchTopResultTests` на ответах `tests/Melogold.Tests/Fixtures/search/`
(«Кино», «Michael Jackson», «Tkay Maidza» — исполнитель; «OK Computer» — альбом «Альбом • Radiohead • 1997»;
«Bohemian Rhapsody» — трек «Видео • Queen»). Их можно взять готовыми.

- Здесь `musicCardShelfRenderer` уже разбирается (`music_parsers.rs`, «как строка списка») — нужно поднять его в
  крупную карточку над выдачей и убрать повтор строкой ниже.
- Правило без карточки: имя исполнителя из выдачи = запрос после нормализации — строчные, ё → е, оставить буквы и
  цифры, между словами один пробел («Ёлка-Палка!» → «елка палка», «AC/DC» → «ac dc»). Тест «без карточки»: из того же
  ответа заменить полку карточки обычной полкой с её строками.
- Совпадение «тот же объект» для повтора: трек — по videoId, альбом и исполнитель — по browseId, плейлист — по
  playlistId.
- «Слушать» у исполнителя — все его песни (плейлист «Песни» со страницы исполнителя), не вышло — популярные треки
  со страницы; у альбома — треки альбома. Пока грузится — кнопка выключена; ошибка сети — всплывающее сообщение.
- Фото исполнителя в карточке приходит 120 px — запросить крупнее (как обложки: хвост `=w240-h240-l90-rj`).
- Перед сохранением ответов в репозиторий вычистить `responseContext` (там `visitorData` — идентификатор посетителя)
  и поля отслеживания (`trackingParams`, `clickTrackingParams`, `loggingContext`).
- Скругление карточки — как у элемента страницы, не как у диалога (на Windows сначала было неверно).
