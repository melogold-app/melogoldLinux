# Тест очереди при проверке «вы не бот» падает под нагрузкой

Статус: открыто.

## Что случилось (09.10.2026)

При выпуске 0.1.11 `scripts/release.sh` упал на тесте
`downloads::tests::bot_check_puts_the_whole_queue_on_hold_with_one_request`
(`crates/melogold-playback/src/downloads.rs`):

```
assertion `left == right` failed: порядок очереди сохранён
  left: ["c", "a", "b"]
 right: ["a", "b", "c"]
```

Отдельно тест прошёл 12 раз из 12, падает только под нагрузкой: сборка шла параллельно со сборкой пакетов. Повторный
выпуск прошёл. С изменениями 0.1.11 (лирика, фокус) не связан.

## Решение

Разобраться, откуда берётся порядок в `waiting`. Скорее всего, треки встают в ожидание в порядке, в котором их задачи
дошли до проверки, а не в порядке очереди. Если так, при проверке «вы не бот» пользователь видит, что очередь
скачиваний переставилась (задание 0013 обещает «порядок сохранён»). Чинить в коде: ставить в ожидание по индексу
очереди, а не по времени прихода. Таймингами в тесте не прикрывать.

## Проверка

Тест 200 раз подряд под нагрузкой: `stress-ng --cpu 0` или параллельная `cargo build --release`, плюс
`cargo test -p melogold-playback --lib bot_check_puts`.
