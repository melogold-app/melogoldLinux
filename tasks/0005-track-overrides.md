# Своё название, исполнитель и альбом трека

Статус: сделано — показ, правка, синк (срезы 4–5), поиск текста (срез 6) и копия библиотеки (срез 8). Сервер готов: контракт — `melogoldServer/docs/API.md` §4.8 (`track.override.set`, `overrides`), сервер 0.1.1 работает на живом сервере; образец — Android 0.1.10.

Общая часть (что нужно пользователю, как должно быть, синк, тексты) — `melogoldWindows/tasks/0011-track-overrides.md`.

Коротко: собранный из разрозненных видео YouTube альбом (обход цензуры) должен выглядеть одним альбомом на всех
устройствах. Решение пользователя (2026-09-26): на сервере только текст — название, исполнитель, альбом; обложки и
файлы не храним.

## Linux

- Таблица правок в локальной базе; правка применяется в одном месте при показе трека (строки, плеер, MPRIS,
  «Сохранить файлом»).
- Меню трека → «Изменить сведения…» (`AdwDialog` с `AdwEntryRow`), выделенное → «Указать альбом…».
- Поиск текста: LrcLib сначала по правленым названию и исполнителю.
- Синк: op `track.override.set` и `overrides`, только если вид есть в `features.sync.kinds`.

## Как сделано в Linux (срез 4)

- база: схема 7 — `track_overrides` (правки) и `synced_overrides` (снимок сервера для синка, срез 5);
  `crates/melogold-data/src/overrides.rs` — правка целиком, как у сервера (обрезка по краям и до 500 единиц
  UTF-16, пустое поле — без правки, все пустые — правки нет); правки держатся в памяти библиотеки;
- показ — одна точка `Library::display` (`MainWindow::display`): строки треков, панель плеера, «Сейчас играет»,
  очередь, MPRIS и теги «Сохранить файлом». В базе у трека остаётся то, что дал YouTube, и в действия (♡,
  плейлисты, загрузки) идёт исходный трек — лайк с оригинальными метаданными правку не сбрасывает;
- фильтр и сортировка списков Библиотеки и «В библиотеке» при поиске — по своему и по оригинальному названию,
  без учёта регистра и для кириллицы;
- меню трека → «Изменить сведения…» (окно «Сведения о треке» — `AdwAlertDialog` с полями `GtkEntry`: у
  `AdwEntryRow` нет серой подсказки, а в пустом поле серым должно быть как на YouTube; «Как на YouTube» снимает
  правку); выделенное → «Указать альбом…» (по умолчанию общий альбом, иначе название своего
  плейлиста) с плашкой «Альбом указан: …»;
- тексты — у Android (`strings_menu.xml`), у Windows их пока нет: в Linux они в `LINUX_ONLY`;
- тесты: `overrides.rs` (пустые поля, обрезка по UTF-16), `library.rs` (показ поверх YouTube, поиск по обоим
  названиям, «Указать альбом…», правки после перезапуска); снимки `12h-details`, `12i-album`.

## Синк (срез 5)

- `crates/melogold-server/src/sync.rs`: правки сравниваются со снимком сервера (`synced_overrides`) и уходят op
  `track.override.set` целиком (снятая правка — op без полей), только если сервер перечисляет вид в
  `features.sync.kinds`; строки `overrides` ответа ставят правку и здесь, и в снимок;
- живая проверка (`MELOGOLD_LIVE=1 cargo test -p melogold-server --test live`): правка на одном устройстве видна на
  другом, снятие правки доходит обратно за секунды по SSE.

Поиск текста (срез 6): `LyricsFetcher::fetch` спрашивает LrcLib сначала по своим исполнителю и названию, потом по
очищенному оригиналу; «Найти другой текст…» подставляет в запрос свои названия.

Копия библиотеки (срез 8): таблица `TrackOverride` формата копии (`backup-format.md` §2) — экспорт из
`track_overrides`, импорт с правилом «побеждает более поздний `updatedAt`» (`melogold-data/src/backup.rs`).
