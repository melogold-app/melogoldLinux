# Дизайн-доктрина: выжимка руководств платформы, реестр исключений, аудит всех экранов

Статус: сделано — выжимка, реестр и аудит 2026-10-07; расхождения — задания 0018–0024

Те же задания: `melogoldiOSmacOS/tasks/0022-design-doctrine-audit.md`, `melogoldAndroid/tasks/0020-design-doctrine-audit.md`, `melogoldWindows/tasks/0022-design-doctrine-audit.md`.

Пользователь (2026-10-01): нужна не россыпь примеров, а технология: ядро — системный дизайн платформы, «мы на правах гостя
делаем то, что выглядит гармонично»; поверх — свои исключения там, где музыкальному клиенту системного мало; и список того,
что по умолчанию обязан уметь каждый элемент (например, у списка — выделение нескольких), с проверкой, что это работает.
«Это уберёт самую главную проблему — неопределённость, которая порождает новые баги».

Доктрина — `docs/DESIGN-DOCTRINE.md` (одинаковая во всех репозиториях). Это задание переводит её на этот клиент.

## Что сделать

1. **Выжимка** `docs/design/PLATFORM.md`: прочитай руководства ядра ([GNOME HIG](https://developer.gnome.org/hig/), [libadwaita](https://gnome.pages.gitlab.gnome.org/libadwaita/doc/main/)) и запиши коротко по разделам шаблона —
   что говорит руководство и какой системный компонент мы берём для каждого элемента. Дата сверки и версия системы — в
   шапке.
2. **Исключения** `docs/design/EXCEPTIONS.md`: уточни общие строки (правило, которое нарушаем; что сохраняем; файлы) и
   допиши свои исключения клиента. Своё, которое нельзя объяснить, — переделать на системное (в аудит).
3. **Аудит** `docs/design/AUDIT.md`: пройди все экраны по контрактам §4 (любой экран, список треков, полки, меню, кнопки,
   поиск, листы, плеер, настройки). Каждое расхождение — в таблицу и в задание `tasks/` (мелкие можно группами по экрану).
4. Исправляй по заданиям аудита, начиная с самых заметных пользователю.

## Опыт Windows (сделано там 2026-10-07)

Как шло на Windows (`melogoldWindows/docs/design/`, коммиты 25a6a9f, 87b6504, b48b8cf) — чтобы не наступать заново:

- Выжимку писать по самим страницам руководства (для GNOME — [GNOME HIG](https://developer.gnome.org/hig/) и
  [libadwaita](https://gnome.pages.gitlab.gnome.org/libadwaita/doc/main/)), с датой сверки и версией GNOME/libadwaita,
  не по памяти: на Windows сверка сразу нашла расхождения в собственном свежем коде.
- Что нашлось на Windows — проверить здесь в первую очередь:
  - у карточек полок не было меню по правому щелчку и с клавиатуры (§4.3) — у альбома, плейлиста, исполнителя должно
    быть то же меню коллекции, что «…» в их шапке; у строк этих коллекций в списках — тоже;
  - Esc в поле поиска уводил назад со страницы — по §4.6 Esc в поле только снимает фокус;
  - сетка в несколько колонок при вертикальной прокрутке — по строкам: порядок «вниз по колонке» экранный диктор
    (Orca) читает как 1, 4, 2, 5, 3;
  - своё всплывающее сообщение «Отменить» не озвучивалось — у `AdwToast` озвучка своя, но проверить, что все
    сообщения идут через него;
  - своё движение (столбики «играет», появление плашек) должно останавливаться при выключенных анимациях
    (`gtk-enable-animations`, «Уменьшение движения» в GNOME);
  - скругления: элемент внутри страницы и всплывающее/диалог скругляются по-разному — взять значения libadwaita,
    а не одно число на всё.
- Esc как «Назад» по страницам: на Windows руководство против, пользователь оставил (2026-10-07, «пока как есть»).
  Здесь — как велит GNOME HIG; если расходится с `docs/PROMPT.md`, записать исключением и спросить пользователя.
- Пункты, которые проверяются только окном (темы, крупный шрифт, узкое окно, зоны нажатия), — отдельным заданием на
  снимки, если в этой сессии нельзя запускать клиент.
