# Ссылки: поделиться треком, альбомом, плейлистом; открыть ссылку Spotify, Apple Music, Яндекса

Статус: сделано — утверждено пользователем 2026-09-30. Контракт сервера — `melogoldServer/tasks/0003-share-links.md` (дальше `docs/API.md`)

Те же задания: `melogoldAndroid/tasks/0017-share-links.md`, `melogoldWindows/tasks/0016-share-links.md`, `melogoldiOSmacOS/tasks/0019-share-links.md`. Сервер — `melogoldServer/tasks/0003-share-links.md`.
Образец — Android (делается сейчас, `melogoldAndroid/tasks/0017-share-links.md`).

## 1. Что нужно пользователю

Отправить другу трек, альбом или плейлист ссылкой: у кого есть Melogold — открывает в приложении и сохраняет себе, у
кого нет — слушает на YouTube. И обратно: друг прислал ссылку Spotify, Apple Music или Яндекс Музыки — она открывается
в Melogold тем же треком или альбомом.

## 2. Как должно быть (одинаково на всех клиентах)

- **Поделиться** (меню трека, альбома, артиста, плейлиста; системное «Поделиться»):
  - трек из каталога → `https://music.youtube.com/watch?v=<id>`, обычное видео → `https://www.youtube.com/watch?v=<id>`;
  - альбом → `https://music.youtube.com/browse/<browseId>`; артист → `https://music.youtube.com/channel/<browseId>`,
    канал YouTube → `https://www.youtube.com/channel/<id>`;
  - плейлист YouTube → `https://music.youtube.com/playlist?list=<id>`;
  - **свой плейлист** → если сервер объявил `features.share`: `POST /shares` (название, треки по порядку, до 1000) →
    ссылка `…/s/<код>`; без входа, без сервера или без функции → `https://www.youtube.com/watch_videos?video_ids=…`
    (первые 50) и подпись «Ссылка откроет первые 50 треков на YouTube»;
  - текст сообщения: «<Название> — <исполнитель>» и ссылка.
- **Мои ссылки:** Аккаунт › «Мои ссылки» (`GET /shares`): название, треков, дата; «Скопировать ссылку», «Удалить»
  (`DELETE /shares/{id}`: ссылка перестаёт открываться).
- **Открыть ссылку Melogold** — `melogold://share?v=1&url=…&id=…` и `https://<сервер>/s/<код>` (открыта из системы,
  вставлена в поиск, прислана через «Поделиться» в приложение):
  - `GET <url>/shares/<id>` без входа (сервер ссылки может быть чужим) → экран «Плейлист по ссылке»: название, треки,
    «Слушать», «Перемешать», «Сохранить в Библиотеку» (создаёт свой плейлист с этими треками и их метаданными);
  - `404` → «Ссылка удалена или неверна»; нет сети → обычная ошибка сети с «Повторить».
- **Ссылки других сервисов** — Spotify, Apple Music, Яндекс Музыка, Deezer, Tidal, SoundCloud (вставлены в поиск,
  открыты, присланы в приложение):
  - **Уточнение 2026-09-30:** song.link без ключа теперь отвечает `401 PUBLIC_API_ACCESS_DEPRECATED`. Без ключа
    запрос к нему не делать: прочитать начало страницы самой ссылки (до ~400 КБ, User-Agent браузера), взять название и
    исполнителя из `<title>` / `og:title` / `og:description` по правилам сервиса и искать на YouTube Music. Образцы с
    реальными заголовками: Android `providers/songlink/PageTitles.kt` (тесты с HTML-фикстурами), Apple
    `Packages/MelogoldKit/Sources/MelogoldInnerTube/ExternalLinks.swift`. song.link — только если в сборке задан ключ.
  - `GET https://api.song.link/v1-alpha.1/links?url=<ссылка>` → `linksByPlatform.youtubeMusic`, иначе `youtube` →
    videoId или browseId → открыть трек или альбом;
  - song.link не нашёл или недоступен → поиск по названию и исполнителю (из `entitiesByUniqueId` ответа или из
    заголовка страницы);
  - плейлисты других сервисов — «Импорт плейлистов из других сервисов появится позже» (отдельная задача);
  - ключ API не нужен (≈10 запросов в минуту на IP): запросы по одному, ответы кешировать на сутки.
- Схему `melogold://share` регистрировать вместе с `melogold://server` (API §7 сервера).
- Тексты: «Поделиться», «Скопировать ссылку», «Ссылка скопирована», «Мои ссылки», «Удалить ссылку», «Плейлист по
  ссылке», «Сохранить в Библиотеку», «Сохранено в Библиотеку», «Ссылка удалена или неверна», «Ссылка откроет первые 50
  треков на YouTube».

## 3. Linux

- «Поделиться» — «Скопировать ссылку» в меню; `melogold://share` — `x-scheme-handler/melogold` в .desktop-файле вместе с
  `melogold://server`; ссылки в поле поиска.

## 4. Проверка

- Юнит-тесты разбора ссылок (`melogold://share`, `/s/<код>`, music.youtube.com, youtube.com, Spotify, Apple Music,
  Яндекс, Deezer) и ответа song.link (фикстура).
- Живой локальный сервер: поделиться своим плейлистом → открыть ссылку на другом устройстве без входа → сохранить;
  удалить ссылку → «Ссылка удалена».
